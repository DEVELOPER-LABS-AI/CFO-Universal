## New Models

### UtilizationSnapshot

Point-in-time utilization record for a single staff member over a specific period. Follows the `ClientMetrics` snapshot pattern: append-only, immutable once generated, period-bounded.

```prisma
// ============================================================================
// FEATURE 16: UTILIZATION & BENCH COST
// ============================================================================

/// Point-in-time utilization metrics for a staff member over a specific period.
/// Generated by scheduled cron (weekly) or manual trigger. Immutable once created.
/// Follows the ClientMetrics snapshot pattern for period-based analytics.
model UtilizationSnapshot {
  id                String                @id @default(uuid())
  organization_id   String
  staff_id          String

  // Period boundaries (inclusive)
  period_start      DateTime
  period_end        DateTime

  // Hours breakdown
  available_hours   Decimal               @db.Decimal(8, 2)  // Working days in period * standard daily hours
  billable_hours    Decimal               @db.Decimal(8, 2)  // Hours billed to clients (from timesheet or allocation)
  non_billable_hours Decimal              @db.Decimal(8, 2)  // Productive non-billable hours (internal projects, training)
  bench_hours       Decimal               @db.Decimal(8, 2)  // Idle hours: available - billable - non_billable

  // Calculated metrics
  utilization_rate  Decimal               @db.Decimal(5, 2)  // Percentage: billable / available * 100
  bench_cost        Decimal               @db.Decimal(10, 2) // Monetary: bench_hours * hourly cost rate

  // Cost rate used for bench cost calculation (hourly equivalent)
  cost_rate_hourly  Decimal               @db.Decimal(10, 2) // The hourly cost rate used (derived from true_cost or rate)
  cost_rate_source  String                @db.VarChar(20)     // 'true_cost' or 'rate' -- which field was used

  // Data provenance
  data_source       UtilizationDataSource // How billable hours were determined

  // Alert tracking (for deduplication across consecutive snapshots)
  alert_level       String?               @db.VarChar(20)     // 'WARNING', 'CRITICAL', or null (within target)

  // Metadata
  generated_at      DateTime              @default(now())     // When this snapshot was computed
  created_at        DateTime              @default(now())
  updated_at        DateTime              @updatedAt

  // Relations
  organization      Organization          @relation(fields: [organization_id], references: [id], onDelete: Cascade)
  staff             Staff                 @relation(fields: [staff_id], references: [id], onDelete: Cascade)

  // Constraints: one snapshot per staff per period
  @@unique([staff_id, period_start, period_end])

  // Query indexes
  @@index([organization_id])
  @@index([staff_id])
  @@index([organization_id, period_start, period_end])
  @@index([staff_id, period_start])
  @@index([organization_id, alert_level])
  @@index([generated_at(sort: Desc)])

  @@map("utilization_snapshots")
}
```

**Design Notes**:
- `available_hours`: Uses `Decimal(8,2)` -- max 99999.99 hours, well beyond any realistic period. Matches project convention for hour tracking.
- `utilization_rate`: `Decimal(5,2)` matches `ClientMetrics.actual_margin` pattern (0.00 to 100.00).
- `bench_cost`: `Decimal(10,2)` matches all monetary fields in the schema (e.g., `RevenueRecord.amount`, `Staff.rate`).
- `cost_rate_source`: Simple varchar instead of enum because it only has two values and won't grow. Avoids migration overhead of a two-value enum.
- `alert_level`: Nullable varchar. `null` means within target. Used by the deduplication logic during snapshot generation to compare with previous snapshot.
- `@@unique([staff_id, period_start, period_end])`: Enforces one snapshot per staff per period. Upsert during generation uses this constraint.
- Soft delete is intentionally omitted -- snapshots are immutable historical records and should never be deleted.

### UtilizationTarget

Organization-level utilization thresholds with optional per-staff-type overrides. Drives dashboard color coding and alert generation.

```prisma
/// Configurable utilization thresholds for an organization.
/// Supports a default target plus optional overrides per staff type.
/// Drives color-coded status indicators (green/yellow/red) and alert triggers.
model UtilizationTarget {
  id                   String   @id @default(uuid())
  organization_id      String

  // Optional staff type scope (null = organization-wide default)
  staff_type           String?  // Matches Staff.staff_type (dynamic role from StaffRole config)

  // Thresholds (percentages, 0-100)
  target_rate          Decimal  @db.Decimal(5, 2)  // Target utilization (e.g., 80.00)
  warning_threshold    Decimal  @db.Decimal(5, 2)  // Below this = warning (e.g., 70.00)
  critical_threshold   Decimal  @db.Decimal(5, 2)  // Below this = critical (e.g., 50.00)

  // Working hours configuration
  standard_daily_hours Decimal  @db.Decimal(4, 2)  @default(8.00) // Hours per working day (default 8)

  // Feature toggle
  enabled              Boolean  @default(true)     // Can disable alerts without deleting config

  // Timestamps
  deleted_at           DateTime?                   // Soft delete
  created_at           DateTime @default(now())
  updated_at           DateTime @updatedAt

  // Relations
  organization         Organization @relation(fields: [organization_id], references: [id], onDelete: Cascade)

  // Constraints: one target per org per staff type (null staff_type = default)
  @@unique([organization_id, staff_type])

  // Query indexes
  @@index([organization_id])
  @@index([organization_id, enabled])

  @@map("utilization_targets")
}
```

**Design Notes**:
- `staff_type` is `String?` (nullable) to match the `Staff.staff_type` column (which is a dynamic string backed by `StaffRole`). `null` means the organization-wide default.
- `@@unique([organization_id, staff_type])`: Ensures at most one default (null staff_type) and one override per staff type per org.
- `standard_daily_hours` is configurable per target, allowing different roles to have different working hour assumptions (e.g., part-time designers at 6 hours/day).
- `Decimal(4,2)` for `standard_daily_hours`: Range 0.00 to 99.99, sufficient for 0-24 hour days.
- Validation constraint: `warning_threshold < target_rate` and `critical_threshold < warning_threshold` enforced at the application layer (Zod schema), not at the database level, following project convention.

1. Add `UtilizationDataSource` enum
2. Create `utilization_snapshots` table with all columns, constraints, and indexes
3. Create `utilization_targets` table with all columns, constraints, and indexes
4. Add `UTILIZATION_WARNING` and `UTILIZATION_CRITICAL` to `NotificationType` enum

### Pre-Migration Checklist
- [ ] Verify database connection: `npx prisma migrate status`
- [ ] Ensure `.env` uses pooler URLs (port 6543 for DATABASE_URL, port 5432 for DIRECT_URL)
- [ ] Review migration SQL before applying

### Rollback Procedure
```sql
-- Reverse migration (if needed)
DROP TABLE IF EXISTS utilization_snapshots;
DROP TABLE IF EXISTS utilization_targets;
DROP TYPE IF EXISTS "UtilizationDataSource";
-- Remove enum values from NotificationType (ALTER TYPE ... cannot remove values in PG; requires type recreation)
```

**Note**: Removing enum values from PostgreSQL requires recreating the enum type. For a true rollback, the migration should be marked as rolled back and a new migration created to handle the enum type recreation.

## Validation Rules (Zod Schemas)

### UtilizationSnapshot (write validation -- used during snapshot generation)

```typescript
const utilizationSnapshotCreateSchema = z.object({
  organization_id: z.string().uuid(),
  staff_id: z.string().uuid(),
  period_start: z.coerce.date(),
  period_end: z.coerce.date(),
  available_hours: z.number().min(0),
  billable_hours: z.number().min(0),
  non_billable_hours: z.number().min(0),
  bench_hours: z.number().min(0),
  utilization_rate: z.number().min(0).max(100),
  bench_cost: z.number().min(0),
  cost_rate_hourly: z.number().min(0),
  cost_rate_source: z.enum(['true_cost', 'rate']),
  data_source: z.enum(['TIMESHEET', 'ALLOCATION', 'BLENDED']),
  alert_level: z.enum(['WARNING', 'CRITICAL']).nullable(),
}).refine(data => data.period_end > data.period_start, {
  message: 'period_end must be after period_start',
});
```

### UtilizationTarget (write validation -- used in settings UI)

```typescript
const utilizationTargetSchema = z.object({
  organization_id: z.string().uuid(),
  staff_type: z.string().min(1).nullable(),
  target_rate: z.number().min(0).max(100),
  warning_threshold: z.number().min(0).max(100),
  critical_threshold: z.number().min(0).max(100),
  standard_daily_hours: z.number().min(1).max(24).default(8),
  enabled: z.boolean().default(true),
}).refine(data => data.warning_threshold < data.target_rate, {
  message: 'Warning threshold must be less than target rate',
}).refine(data => data.critical_threshold < data.warning_threshold, {
  message: 'Critical threshold must be less than warning threshold',
});
```

## Index Strategy

| Table | Index | Purpose |
|-------|-------|---------|
| `utilization_snapshots` | `(staff_id, period_start, period_end)` UNIQUE | Prevent duplicate snapshots; upsert key |
| `utilization_snapshots` | `(organization_id)` | Org-scoped queries (RLS filter) |
| `utilization_snapshots` | `(staff_id)` | Staff detail page: fetch all snapshots for a person |
| `utilization_snapshots` | `(organization_id, period_start, period_end)` | Dashboard: fetch all snapshots for a period |
| `utilization_snapshots` | `(staff_id, period_start)` | Trend queries: ordered by period for a staff member |
| `utilization_snapshots` | `(organization_id, alert_level)` | Alert queries: find all staff in warning/critical state |
| `utilization_snapshots` | `(generated_at DESC)` | Recency queries: find latest snapshot generation run |

| `utilization_targets` | `(organization_id)` | Org-scoped queries (RLS filter) |
| `utilization_targets` | `(organization_id, enabled)` | Active target queries |
